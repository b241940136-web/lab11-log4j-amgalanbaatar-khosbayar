Энэхүү лабораторийн ажлаар Java програмд Log4j 2 санг ашиглан логийг хэрхэн зөв хөтлөх, түвшингүүдийг ангилах, болон командын мөрөөс лог файлд шинжилгээ хийх арга барилд суралцлаа.

1. Төслийн бүтэц ба ангиуд
BankAccount.java: Банкны дансны үлдэгдэл, орлого, зарлагын үйлдлүүдийг гүйцэтгэнэ. Гүйцэтгэсэн үйлдэл бүрийг (TRACE-ээс FATAL хүртэл) логийн түвшингүүдээр бүртгэдэг.

Customer.java: Хэрэглэгчийн мэдээллийг хадгалах бөгөөд имэйл хаягаас домэйн нэр ялгах функцийг агуулсан.

2. Log4j2 Тохиргоо (log4j2.xml)
Логийг дараах хоёр хэлбэрээр хөтлөхөөр тохируулсан:

Console: Терминал дээр өнгөтэй, thread ID болон мөрийн дугаартай харагдана.

RollingFile: logs/app.log файлд хадгалагдана.

RollBySize: Файлын хэмжээ 1 MB хүрэх бүрт шинэ файл үүснэ (архивлагдана).

TimeBased: Өдөр бүр шинэ файл үүснэ.

3. Алдааг оношилсон тухай (Debugging Customer.java)
Алдаа: Customer ангийн getDomain() метод дээр имэйл хаяг null байх үед NullPointerException үүсэж байсан.

Илрүүлсэн арга: Лог файл дотор DEBUG түвшнээр орж ирж буй параметрүүдийг хэвлэхэд email=null гэж гарч ирснээр алдааны эх үүсвэрийг олсон.

Зассан байдал: Иф нөхцөл ашиглан null эсэхийг шалгадаг болгож, хэрэв хоосон бол WARN түвшний лог бичдэг болгож зассан.

4. Шинжилгээ ба Асуултын хариулт
Асуулт: Яагаад tail -f нь cat эсвэл less-ээс илүү хэрэгтэй вэ?

Хариулт: tail -f нь файлыг байнга нээлттэй байлгаж, програм ажиллах явцад шинээр нэмэгдэж буй лог бүрийг real-time (шууд) харуулдаг. Энэ нь програм ажиллаж байх үед алдааг тэр дор нь олж харахад тусалдаг. Харин cat нь зөвхөн тухайн үеийн агуулгыг хэвлээд дуусдаг
